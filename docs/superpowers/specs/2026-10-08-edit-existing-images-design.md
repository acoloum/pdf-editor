# 墨頁 PDF 編輯既有圖片設計

日期：2026-10-08
目標版本：0.21.0

## 目標

讓使用者直接在頁面上點選 PDF 原有的圖片（例如材質證明左下角的統一發票專用章），移動位置及放大縮小。保留現有清單式的轉換流程作為備用入口，並修正既有轉換流程對正常圖章的誤判。另外提供「去除白底」選項，避免沒有透明背景的圖章移動後蓋住底下的表格或文字。

## 背景：現有流程的誤判

0.20.1 已有「轉換既有圖章」功能（`legacy_overlay_conversion.py`），但實際材質證明檔 `115.01.02-2014-F.pdf` 的圖章不會列入候選。這張圖是 387×336 的 ICCBased RGB 影像，沒有 SMask，約 72% 為白底，在整份文件中只用了一次，沒有旋轉。單次使用、非整頁掃描、軸向擺放三項檢查都通過，只有 `_rendered_region_matches` 的外觀比對不過：移除後再放回的頁面與原頁面相比，共有 45 個取樣值差了 3～4（門檻是 2），而且都位在上方表格線條附近，不在圖章範圍內。整份文件重新輸出（`tobytes(garbage=4)`）本身的差距是 0，所以差異來自刪除與插入圖片造成的反鋸齒細微變化，肉眼看不出來。

## 一、外觀比對容許反鋸齒誤差

`_rendered_region_matches` 改為下列條件全部成立才算外觀一致：

1. 兩張渲染圖的寬、高、色版數相同，且內容不為空（維持現狀）。
2. 每個取樣值的差距都不超過 12（原訂 24，審查後收緊：24 會放過蓋在圖章上的淡色內容）。
3. 差距超過 2 的取樣值數量不超過總取樣數的 0.05%。

遇到圖片被其他內容覆蓋、被裁切路徑影響或受繪圖狀態（透明度、混合模式）影響時，會有大片取樣值明顯不同，因此仍然會被拒絕。

選單項目「轉換既有圖章」改名為「編輯既有圖片…」，工具提示同步更新；清單對話框的流程與條件不變。

## 二、直接點圖片編輯

### 可編輯圖片的快速清單

新增 `editable_images_on_page(document, page_number) -> tuple[EditableImage, ...]`，回傳該頁通過快速檢查的圖片（xref、頁碼與矩形）。快速檢查包括：在本頁只畫一次、其他頁面的資源沒有引用同一張圖、不是整頁掃描、軸向擺放未旋轉或鏡射。這一步不做渲染比對，速度很快。`render_page` 渲染時一併計算，結果放在頁面資料的 `images` 欄位；計算失敗時視為空清單。這樣不必另外開背景工作，也不需要額外快取。

### 游標回饋

畫布取得目前頁面的可編輯圖片矩形。滑鼠移到其中一張圖片上、且該位置沒有圖層或文字時，游標改為手指，並在圖片外圍畫出淡青色外框；移開後清除。

### 點選與轉換

點擊時依下列順序判斷：圖層 → 註解選取模式等既有模式 → 文字 → 可編輯圖片 → 平移。也就是說，同一點同時有文字和圖片時，以文字為優先。

點到可編輯圖片時，畫布發出 `image_clicked(EditableImage)`。主視窗在背景執行 `convert_image_at(pdf, image, asset_root)`：先確認這張圖目前仍只在同一頁、同一位置出現一次（避免頁面資料過時而改到別張圖），再只針對它建立候選，並跑完整的安全檢查（含外觀比對），再用與 `convert_legacy_image` 相同的交易流程抽離。狀態列顯示「正在準備編輯圖片…」。轉換期間畫布不接受對該圖片的拖曳。

成功時套用新狀態、選取新圖層並顯示四角控制點，同時記錄「待確認轉換」：圖層 ID 與轉換後的 `revision`。失敗時不改動文件，並在狀態列用繁體中文說明原因，例如「這張圖片在文件中重複使用，無法單獨編輯」或「這張圖片受其他內容影響，無法安全編輯」。

作業期間如果文件版本改變，或工作階段已關閉，就丟棄結果（沿用 `_legacy_stamp_context_is_current` 的判斷方式）。

### 沒有改動就自動還原

待確認轉換存在時，只要發生下列任一情況，就檢查目前 `revision` 是否仍等於轉換後的 `revision`：取消選取或選取其他物件、換頁、存檔、另存、關閉文件、開啟其他文件、復原或重做。如果相等，代表使用者沒有做任何改動，程式就呼叫 `DocumentSession.discard_last()` 撤銷轉換。這會移除最後一筆歷程，而且不留下重做紀錄，所以文件回到未修改的狀態，接著再重新渲染。若 `revision` 已不同（使用者移動、縮放、改角度或勾了去除白底），就清除待確認標記，保留轉換。

復原或重做的情況：先撤銷待確認轉換，這次撤銷就是該次復原的效果，不再額外往前一步。

`History` 新增 `discard_last()`，`DocumentSession` 新增對應的 `discard_last()`（`revision` 加一）。兩者只允許在 `index` 為最後一筆且大於 0 時使用。

## 三、去除白底

- `Overlay` 新增欄位 `remove_white: bool = False`。
- `transformed_png` 在縮放與旋轉之前，依這個欄位處理透明度：RGB 三個值都 ≥ 235 的像素設為完全透明；最小值介於 215 到 235 的像素，透明度依線性比例漸變，讓邊緣柔化、不留白邊；原本就有透明度的像素，與原 alpha 取較小值。畫面顯示與 `flatten_overlays` 輸出共用這個函式，所見即所得。
- 右側「圖章／簽名」面板新增勾選框「去除白底」，切換時透過 `move_layer` 建立一筆歷程。所有圖層都可以用。
- 資產檔不變，取消勾選即恢復原樣。
- 工作層格式：圖層描述允許選填欄位 `remove_white`（布林值），只在值為 true 時寫入。讀取時同時接受有或沒有這個欄位的描述；`WORKSPACE_VERSION` 維持 1。沒有勾選的檔案與舊版程式完全相容；有勾選的檔案用舊版程式開啟時，會因驗證不通過而以靜態 PDF 顯示，外觀不受影響。
- `history.fingerprint` 以 `asdict` 計算，自動涵蓋新欄位。

## 元件邊界

- `legacy_overlay_conversion.py`：放寬外觀比對；新增 `editable_images_on_page` 與 `convert_image_at`，與既有清單流程共用檢查及抽離邏輯。
- `model.py`：`Overlay.remove_white`、`EditableImage`。
- `engine/overlay.py`：去除白底的影像處理。
- `persistent_overlays.py`：選填欄位 `remove_white` 的寫入與驗證。
- `document/history.py`、`document/session.py`：`discard_last()`。
- `ui/canvas.py`：可編輯圖片矩形、游標回饋、`image_clicked` 訊號。
- `ui/stamp_actions.py`：點選轉換、待確認轉換、自動還原、去除白底切換。
- `ui/overlay_panel.py`：去除白底勾選框。
- `engine/render.py`：頁面資料加入 `images`。
- `ui/main_window.py`：選單改名，以及在換頁、存檔、關閉、復原時呼叫自動還原。

## 錯誤處理

所有掃描與轉換都在背景工作中以記憶體副本進行，成功才提交工作階段；任何失敗都不改動文件，並以繁體中文說明原因。快速檢查失敗時，視為該頁沒有可編輯圖片，不顯示錯誤，清單入口仍可使用。

## 測試與驗收

自動測試：

- 外觀比對：模擬反鋸齒的小量差異可以通過；圖片被其他內容覆蓋、受裁切路徑影響時仍然被拒絕；差距大於 12 或超過比例都會被拒絕。
- `editable_images_on_page`：重複使用、整頁掃描、旋轉的圖片不會列出。
- `convert_image_at`：成功時產生圖層且外觀一致；條件不符時拋出含原因的 `EditorError`，文件不變。
- `discard_last`：移除最後一筆、沒有重做紀錄、`dirty` 回到 False。
- UI：點圖片後轉換並選取；沒改動就點空白處，會自動還原且文件未修改；拖曳後再取消選取則保留；換頁及存檔前會自動還原；同一點有文字時選到文字。
- 去除白底：白色變透明、邊緣漸變；顯示與輸出一致；另存重開後設定保留；沒有該欄位的舊工作層照常讀取。

實機驗收（只在本機進行，`115.01.02-2014-F.pdf` 不放進程式庫）：

- 開啟材質證明，直接點左下角圖章，移動並縮放，勾選去除白底後另存。
- 重開後圖章仍可編輯；以渲染比對確認表格、文字與頁碼沒有變化。
- 「編輯既有圖片…」清單也能列出這個圖章。
- 依記憶中的規則，用 `work/build-venv312` 跑測試與建置。

## 限制

- 向量圖章、整頁掃描中的章、重複使用的影像，以及經旋轉或斜切擺放的影像仍不支援。
- 圖片與文字重疊時，點擊會先選到文字，需改用「編輯既有圖片…」清單。
- 去除白底以亮度判斷，接近白色的圖案（例如淡色浮水印）也會一起變透明。
