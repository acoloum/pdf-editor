# 墨頁 PDF 0.24.1 驗收紀錄

驗收日期：2026-10-15
環境：Windows 11 x64（10.0.26300）。

## 本版重點

- 問題：使用者在 Windows 11 存檔覆蓋 OneDrive 桌面上的檔案時一律失敗，只顯示「儲存失敗，請檢查空間、路徑權限及檔案是否被占用」，錯誤紀錄也只有這句概括訊息。
- 原因：Windows 安全性的「受控資料夾存取權」以封鎖模式開啟（`EnableControlledFolderAccess=1`），Defender 事件記錄（事件識別碼 1123）顯示 `LocalPDFEditor.exe` 寫入 `%userprofile%\OneDrive\桌面\每日材證\…` 被封鎖，時間與存檔失敗紀錄一致。實測被封鎖時建立檔案收到的是 `FileNotFoundError`（Errno 2），不是權限錯誤。
- 修正：在目標資料夾建立暫存檔失敗、資料夾確實存在、且系統以封鎖模式啟用受控資料夾存取權（先讀群組原則再讀使用者設定，一般使用者即可讀取）時，改顯示「Windows 封鎖了存檔」，說明原檔未被修改、列出要允許的程式路徑與「Windows 安全性」中的允許步驟，或改用另存新檔。覆蓋原檔、另存新檔、合併、抽取、拆分與輸出 PNG 都套用。
- 實機發現「Windows 安全性」的允許清單頁面顯示「您不具適當權限，因此無法檢視此頁面」：使用者帳號屬於 Administrators 群組，但平常以未提升的權限執行（該群組在權杖中為僅拒絕）。提示因此補上「以系統管理員身分執行 PowerShell」及可直接執行的 `Add-MpPreference -ControlledFolderAccessAllowedApplications` 指令，訊息可按 `Ctrl+C` 複製；用語也改成與 Windows 11 介面一致的「受控資料夾存取權」（原寫成「受控制資料夾存取」），並說明 OneDrive 中桌面、文件、圖片以外的位置不受保護。
- 覆蓋時目標檔被其他程式開啟或設為唯讀，改顯示「檔案正被使用」。
- 背景工作失敗時，錯誤紀錄一併保留實際的例外與堆疊。
- 以虛擬環境執行原始碼時列出底層 Python 的路徑，與 Windows 事件記錄中被封鎖的程式一致；安裝版列出 `LocalPDFEditor.exe` 本身。
- 以原始碼對實際被封鎖的桌面資料夾另存新檔：判定為 `FOLDER_BLOCKED`、實際例外為 `FileNotFoundError`，資料夾內未殘留暫存檔。

## 已知限制

- 文字修改適用於可解碼、局部、橫排文字；不提供直排重排、斜向文字重排或全文自動排版。
- OCR 結果受解析度、壓縮、污點、旋轉、表格線與版面影響；只建立不可見文字層，不重建版面或代替人工校對。
- 頁面比較是像素層比對，字型渲染、掃描噪點、幾何位移、旋轉或頁面尺寸差異都可能被標示；相似度不是內容語意比較。
- 圖章與簽名是寫入頁面的外觀，不是憑證數位簽章；可編輯工作層只由「墨頁 PDF」維護，第三方壓縮、最佳化、列印成 PDF 或移除附件可能將其刪除，之後只能以靜態頁面內容開啟。
- 舊圖章轉換只支援全文件中唯一使用、單一位置且小於頁面 90% 的點陣影像；整頁掃描、重複 Logo／影像與向量章不會列為候選。
- 合併與拆分不重建書籤及文件內部連結。
- 已加密文件另存時不保留加密；程式會先提示。
- 此版本聚焦文字修改、蓋章、手寫或圖片簽名、合併及拆分，未宣稱完整重現 Adobe Acrobat 的所有功能。
